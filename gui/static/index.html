How it works
Detect. Verify. Alert.

    
Classical computer vision does the thinking; libraries do the heavy lifting.

  

    
Detect
A fast and a slow background model disagree about anything that stopped: that is a static candidate.

    
Verify
Edge test, shadow test, lighting check and an optional CNN decide: abandoned, removed, shadow or just moved.

    
Alert
Owner distance in real metres, a timer, a state machine, then snapshot, clip and notification.

  

  

    
01
Camera-health gate
Blocked, blurred, frozen, shifted or disconnected camera raises a tamper alarm and pauses object logic.

    
02
Dual background
A fast model absorbs a stopped object in seconds, a slow model remembers the empty scene. Static candidate = long-term foreground and not short-term foreground.

    
03
Shadows & lighting
Brightness-ratio, colour and texture tests plus a global lighting-versus-scene-change check keep false alarms down.

    
04
Verification
The edge test on the blob boundary decides abandoned versus removed; an optional 6-channel CNN (current plus background crop) can override it.

    
05
Owner logic
The nearest person when the object stopped is the owner; distance is measured on the floor plane and the owner is re-identified after tracker ID switches.

    
06
State machine
CANDIDATE → STATIC → UNATTENDED → ALARM, with presence authentication through occlusion. Every alarm saves a snapshot, a CSV row and an evidence clip.
